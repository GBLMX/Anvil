# 0.6.x Plugin Distribution, Marketplace, and Download Manager

Status: `0.6.0`–`0.6.3` landed; the official-only distribution path and
release workflow are landed. The signed index/revocation verifier and cache are
landed; the marketplace client/UI remains planned;
production signing keys and release secrets are external. The plugin API is
frozen at `1.0.0`. The workspace version is frozen at `0.6.0` for internal
polish; no release tags or public releases are produced during this phase.

Scope: signed plugin packages, local install/update state, a bounded download
manager, installed-plugin management, and a marketplace index client/UI. The
marketplace is a trusted built-in surface, not a runtime plugin.

## 1. Principles

1. **The marketplace is an index, not a trust root.** Trust comes from package
   signatures, publisher identity, source class, and explicit user consent.
2. **Install is not enable, and enable is not activate.** An installed plugin
   stays inert until the user enables it; activation remains `0.4.6`.
3. **No silent updates.** Update checks are explicit or opt-in; a running host
   is stopped/replaced only after user confirmation.
4. **The download manager is trusted infrastructure.** It runs outside the
   plugin host; plugins never receive network access through it.
5. **Network policy stays central.** Marketplace/package fetches use the
   gateway's exact-host allowlist, HTTPS-only rule, redirect rejection, and
   body/time/concurrency caps. No arbitrary manifest URLs.
6. **Verify before extract.** Digest and signature verification happen before
   archive extraction or install.
7. **Atomic install/update.** Stage, verify, fsync, then rename; failed updates
   leave the previous version usable.
8. **Permissions are keyed by plugin id and manifest hash.** A new manifest or
   widened permissions requires new consent.
9. **Degrade visibly.** Offline, cached-index, stale-index, revoked, and
   incompatible states are explicit; the editor remains usable.
10. **Bound everything.** Package size, file count, index size, queue length,
    retries, disk quota, and UI lists have hard caps.

## 2. Current state

- Plugin discovery supports bundled official roots, managed roots, and child
  directories of `ANVIL_PLUGIN_DIR`; local entries are `local-user`.
- Signed `.anvil-plugin` local install exists with detached Ed25519
  signatures, fsroot-confined extraction, a bounded download queue, and a
  content-addressed store with `state.json`, plus an installed-plugin manager
  with enable/disable, uninstall, and rollback.
- Official release layouts ship `install.sh`, bundled public plugin sources,
  and optional signed packages. `-install-bundled` imports/updates the managed
  store idempotently. Signed index/revocation documents verify and cache; the
  marketplace UI and indexed install flow remain pending.
- `anvil-api` freezes complete v1 DTOs for every catalog method. The editor,
  production plugin-host proxy, and independent contract consumer
  exercise the same contract; generated TypeScript/Luau/JSON Schema and `tsc`
  CI are current.
- Plugin-host `session.hello` and the gateway advertise API `1.0.0`; manifests
  reject missing or incompatible API lines before loading.
- Manifest-declared `onCommand` entries and dynamic
  `editor.register_command` commands dispatch from the command palette and
  activate a per-command host.
- The gateway exposes `pkg.download`, `pkg.install`, `pkg.installed`,
  `pkg.set_enabled`, `pkg.uninstall`, and `pkg.rollback`. Downloads and
  installs use a separate fetch-only installer gateway role; the editor
  gateway rejects package fetch/install. `GatewayClient::fetch` is the typed
  installer-only wrapper for bounded `sys.fetch` metadata.
- `:plugin-list` opens the installed-plugin manager with enable/disable,
  confirmed uninstall, rollback, and store-size display. `:pkg install-file`
  reviews and installs local signed packages. Marketplace UI remains pending.
- The tag release workflow produces signed `SHA256SUMS`, an SPDX SBOM, and a
  GitHub build-provenance attestation. Production signing keys are external
  release secrets; a marketplace index remains gated on signing/provenance.

## 3. Release slices

### 0.6.0: Plugin API v1 freeze gate

Status: done. The production editor RPC service is owned by
`PluginSupervisor`; its socket is passed through `PluginSession`/`HostSession`
and the host proxy reaches the live active buffer.
API version `1.0.0`, complete DTO catalog, generated bindings, manifest freeze
on `plugin.json`, and the ADR-0013 two-consumer test gate are done.


- Complete request/response DTOs and stable errors for every v1 method in
  ADR-0003; method constants alone are not a contract.
- Publish `docs/spec/plugin-api-v1.md` as the single normative SPEC. Rust
  types, JSON Schema, TypeScript, and Luau/LuaLS stubs are generated
  projections; do not maintain per-language specs. CI checks examples, method
  catalog, and generated artifacts.
- Rust remains the single source of truth. Generated TypeScript declarations and
  Luau/LuaLS stubs must cover every DTO and method, with `tsc --noEmit` and a
  LuaLS or schema/golden check in CI.
- `session.hello` carries the same `api_version` on both sides; a plugin
  declares its required API range in the manifest. Missing or incompatible
  versions fail before plugin loading.
- Freeze one manifest path and schema. ADR-0003 says `Anvil.toml`; discovery
  currently uses `plugin.json`; the freeze must pick one and remove the
  ambiguity.
- Parity tests: first-party editor implementation and plugin-host proxy return
  identical DTOs, errors, revisions, and cancellation behavior.
  The proxy is production-wired: `PluginSupervisor` owns an editor RPC socket,
  `HostSession` passes it to the host, and TUI polling applies live edits.
- ADR-0013 gate: at least two consumers, the official standard edition and an
  independent distribution/test consumer, must exercise the same contract
  before `API_VERSION` becomes `1.0.0`.
- If the gate is not met, keep `0.x` experimental and block marketplace
  publishing; do not label generated stubs stable early.

### 0.6.1: Package and signed index format

Status: package archive/signature, content-addressed store, local install, and
release-layout packaging are landed. ADR-0021 is accepted; the signed index and
revocation verifier/cache are implemented in `go/internal/pluginindex`.

Store/state freeze: [0.6.1 package store plan](0.6.1-package-store-plan.md).

- Decision ADR: [ADR-0021](adr/0021-signed-plugin-index.md) freezes the
  signed index and revocation envelopes, publisher identity, compatibility
  fields, anti-rollback state, revocation records, `MAX_INDEX_BYTES`, and
  `MAX_REVOCATION_BYTES`. Package archive/signature and store layout remain
  [ADR-0020](adr/0020-content-addressed-plugin-store.md).
- The manifest declares its required API range; the index and installer reject
  packages outside the running `API_VERSION` range.
- No package enters a marketplace index until the release signing/provenance
  gate passes. Unsigned packages are allowed only for explicit local/dev
  installs and are never indexable.
- Package contains manifest, entry, assets, and checksums; no symlinks, hard
  links, absolute paths, `..`, or device files.
- Index is signed and versioned; anti-rollback metadata is defined.
- Source class is derived from signature/install origin, never from the
  manifest's self-declaration.
- Local install from a package file works without network.
- Tests: invalid signature, digest mismatch, archive traversal, duplicate
  plugin id, incompatible API version, oversized archive.

### 0.6.2: Download manager

Status: installer gateway role, bounded `pkg.download` queue, and typed
`GatewayClient::fetch` are landed. Index-to-download integration remains
pending.

- Add a trusted installer gateway role, separate from the editor session:
  `GatewaySession::start_installer(workspace)` passes
  `-plugin-id anvil-installer`, `-allow-fetch`, an exact
  `-fetch-allow <host-list>`, `-fetch-max <package-cap>`, and
  `-fetch-timeout`; it passes no `-allow-read`, `-allow-write`, or
  `-allow-exec`.
- `GatewayClient::fetch(url, max_bytes, headers) -> FetchResult` is the
  installer-only typed wrapper. The plugin host never receives this client or
  its token. Package archives stay on `pkg.download`; `sys.fetch` carries only
  bounded index/metadata responses.
- Freeze `MAX_PACKAGE_BYTES` in the 0.6.1 ADR. The index package size must be
  rejected before enqueue when it exceeds that cap; the fetched body must be
  rejected when `Content-Length` or `truncated` exceeds it.
- Keep the MVP in-memory only when the cap fits the fetch body budget. If the
  cap must grow, add a bounded stream-to-file download method before raising
  it; never fall back to an unbounded body.

- Bounded queue with explicit concurrency, retry/backoff, pause/cancel/resume,
  and offline queuing.
- Downloads go to a private cache with a disk quota; temp files are never
  installed directly.
- Fetch policy: exact host allowlist, HTTPS/443, no redirects, decompressed
  body cap, total time cap, no proxy environment.
- Digest and signature verification before the package enters the store.
- Interrupted or corrupt downloads are discarded, not resumed into a valid
  package without verification.
- Tests: cancel mid-stream, network interruption, corrupt digest, redirect
  rejection, disk full, queue cap, concurrent duplicate requests; installer
  session has `sys.fetch` while the editor session does not; non-allowlisted
  host is denied; body over `-fetch-max` is rejected; package over
  `MAX_PACKAGE_BYTES` is rejected before enqueue.

### 0.6.3: Installed-plugin manager

- List installed plugins with version, source class, manifest hash, permissions,
  enabled/disabled state, and update availability.
- Enable, disable, uninstall, and rollback; uninstall never executes plugin
  code.
- Preserve user grants only when the manifest hash and permission set are
  unchanged.
- No activation is triggered by install, enable, or update.
- Tests: permissions diff, disable while running, uninstall of active plugin,
  rollback, missing package, read-only store.

### 0.6.4: Marketplace browse and detail
Depends on `0.6.2` and the `0.5.7` notification/progress UI.

- Browser/search over the signed cached index; offline and stale-index states
  are visible.
- Detail shows publisher, source class, signature state, permissions, size,
  compatibility, version history, and revocation status.
- Install action is disabled with an explicit reason for incompatible or
  revoked packages.
- No arbitrary URL entry; only index-provided packages or local files.
- Tests: empty index, stale cache, revoked package, incompatible platform,
  long descriptions, narrow layout.

### 0.6.5: Install, update, and consent
Depends on `0.6.4` and the `0.5.7` notification/progress UI.

- Permission consent screen shows added/removed file roots, hosts, executables,
  and API compatibility.
- Update only after the running host is drained/stopped and its token revoked.
- Install/update is atomic; a failed verification or rename leaves the prior
  version and lockfile intact.
- No automatic activation after update; restore enabled state without starting
  the host until an activation event or explicit user action.
- Tests: permission widening, failed host stop, crash during update, rollback,
  lockfile corruption, downgrade attempt.

### 0.6.6: Revocation and provenance

- Signed revocation list with an explicit check policy; revoked packages are
  disabled on next check and cannot be installed.
- Publisher verification, SBOM/provenance display, and signature-chain errors
  are visible in detail.
- Emergency disable is local and does not depend on the network.
- Tests: revoked installed plugin, revoked package install, expired signature,
  unknown publisher, offline revocation cache.

## 4. Architecture

```text
TUI (trusted)
  -> plugin manager / marketplace view
  -> install service (session-owned)
       -> installer gateway role (installer-only token)
            -allow-fetch -fetch-allow <exact hosts> -fetch-max <cap>
            no read / write / exec grants
       -> index client       -> GatewayClient::fetch
       -> download manager   -> private cache
       -> verifier           -> digest + signature + source
       -> installer          -> stage + atomic rename + lockfile
  -> plugin discovery/activation (0.4.6)
```

Required boundaries:

- **No plugin-host networking.** The download manager never runs in the host
  sandbox and never hands network handles to it.
- **The editor session has no fetch grant.** Only the installer gateway role
  receives `sys.fetch`, with a fixed host list and package-size cap.
  `GatewayClient::fetch` is never exposed to the plugin host or plugin API.
- **No plugin-owned UI.** Marketplace and manager screens are built-in, using
  the focus/overlay/palette primitives from `0.5.x`.
- **No direct filesystem from the TUI.** Store/lockfile operations go through
  the session/install service with explicit permissions.
- **Store is content-addressed.** `$XDG_DATA_HOME/anvil/plugins/store/<digest>`
  holds verified packages; installed state references a digest, not a mutable
  directory.
- **Local `ANVIL_PLUGIN_DIR` remains supported.** Such plugins are
  `LocalUser`; they are not presented as marketplace or official packages.

## 5. Security invariants

1. An unsigned or unknown package is never `Official` or
   `TrustedDistribution`.
2. A plugin cannot self-declare its source class.
3. A package is verified before extraction; extraction cannot escape the stage
   directory.
4. A manifest update cannot silently widen grants or reuse old approval.
5. A revoked package cannot be installed or activated.
6. The download manager cannot fetch arbitrary hosts or follow redirects.
7. A failed update never removes the previously working version.
8. No install, update, or enable action auto-activates a plugin.
9. The editor gateway has no `sys.fetch`; only the installer role does.
10. A package larger than the frozen cap is rejected before download or before
    verification, never buffered without bound.

## 6. Non-goals

- A public plugin registry service in the same release.
- Automatic background updates by default.
- Remote plugin execution without download verification.
- Plugin-owned marketplace UI, network, or store mutation.
- Delta/binary patching in the first implementation.
- Paid plugins, accounts, ratings, or social features.
- Cross-platform package signing before release signing exists.

## 7. Exit gates

Every slice must satisfy [RELEASE.md](../RELEASE.md), update `CHANGELOG.md`,
`ROADMAP.md`, the threat model, and the relevant ADR, and pass an
installed-binary smoke test.

Additional distribution gates:

- Invalid signature/digest cannot reach the plugin store.
- Archive traversal and symlink escapes are rejected by tests.
- A failed update leaves the prior version and grants intact.
- Permission widening always returns to the consent screen.
- The plugin host has no network path during download/install.
- Offline and revoked states are visible and do not block editing.
- The download queue and install state are bounded and non-blocking.
