# 0.6.1 Package Store and Installed State Plan

Status: proposed. This freezes the package-store layout before the
installed-plugin manager is implemented.

## 1. Problem

`pkg.install` currently extracts a verified package into
`PluginDir/<plugin-id>`. That path is mutable and one-version-only:

- a second install of the same id fails because the destination exists;
- update and rollback have no immutable target;
- installed state cannot identify which bytes the user approved;
- uninstall and garbage collection have no shared store;
- discovery by mutable directory cannot distinguish package versions.

The 0.6.x architecture instead requires a content-addressed store and installed
state that references a digest. The current mutable path must not become the
manager's storage model.

## 2. Decisions to freeze

1. The package digest is the SHA-256 of the compressed `.anvil-plugin` archive.
2. The store is content-addressed at
   `$XDG_DATA_HOME/anvil/plugins/store/<digest>/`.
3. The store contains both the verified archive and a verified extracted tree.
   The archive is the integrity source; the extracted tree is the runtime root.
4. Installed state lives at `$XDG_DATA_HOME/anvil/plugins/state.json`.
5. Installed state references a digest and a manifest hash; it never stores a
   mutable plugin directory as the package identity.
6. Install is not enable. A successful install leaves `enabled: false`.
7. `ANVIL_PLUGIN_DIR` remains a `LocalUser` discovery path, not a package-store
   entry. It never becomes `Official` or `TrustedDistribution`.
8. One plugin id has one active digest. Other retained digests are history for
   rollback, bounded to a small fixed count.
9. Store and state writes are atomic: write a private stage, fsync files and
   parent directories, then rename.
10. The TUI does not write the store directly. Store operations stay behind the
    session/install boundary; the current gateway path is transitional.
11. `XDG_DATA_HOME` unset or empty falls back to `$HOME/.local/share`; a
    missing home directory is an install error, not a cwd-relative store.
12. The plugin data root is `0700`; `state.json`, `state.lock`, and
    `store.lock` are `0600`; store entries are read-only after commit.
13. State mutations are serialized by an exclusive `state.lock`; an
    atomic rename alone does not prevent lost updates between concurrent
    install, update, and uninstall requests.
14. Store payload mutations are serialized by an exclusive `store.lock`.
    Mutations acquire `store.lock` before `state.lock`; uninstall and store
    garbage collection hold it through payload deletion.

## 3. On-disk layout

```text
$XDG_DATA_HOME/anvil/plugins/
  state.json
  state.lock
  store.lock
  store/
    <sha256>/
      package.anvil-plugin
      meta.json
      root/
        plugin.json
        ...
```

`meta.json` is derived from the verified package and the install request:

```json
{
  "digest": "<sha256>",
  "plugin_id": "anvil.official.trim-whitespace",
  "version": "0.1.0",
  "manifest_hash": "<sha256>",
  "permissions": [],
  "installed_at": 0
}
```

`root/` is owner-readable and not user-writable after commit. Store entries are
immutable; a changed archive always produces a different digest.

## 4. Installed state

```json
{
  "version": 1,
  "plugins": {
    "anvil.official.trim-whitespace": {
      "active_digest": "<sha256>",
      "source": "local-file",
      "enabled": false,
      "granted_permissions": [],
      "versions": [
        {
          "digest": "<sha256>",
          "version": "0.1.0",
          "manifest_hash": "<sha256>",
          "installed_at": 0
        }
      ]
    }
  }
}
```

Rules:

- `active_digest` must exist in the store and match the recorded manifest hash.
- `enabled` is separate from installation and activation.
- `granted_permissions` records the consent decision, not the manifest's
  requested permissions.
- A new digest with added permissions requires new consent.
- Removing a plugin from state does not delete the store until no retained
  version references the digest.
- A corrupt state file fails closed for managed plugins; local discovery remains
  available with an explicit status.

## 5. Source classes

- `official`: first-party package published by the release signing process.
- `trusted-distribution`: third-party package accepted through explicit trust.
- `local-file`: signed package installed from an explicit local path.
- `local-user`: unpacked plugin under `ANVIL_PLUGIN_DIR`; never installed state.

Source class is derived from how the package entered the system, never from
`plugin.json`.

## 6. Install transaction

0. Acquire the exclusive `state.lock` before reading or mutating state. Keep
   it through store commit and the state rename.
1. Receive archive and signature paths plus the reviewed digest.
2. Verify archive size, digest, signature, trust, manifest, plugin id, and API
   compatibility.
3. Extract into a private stage under `store/`, using existing fsroot
   confinement and rejecting links, devices, absolute paths, and traversal.
4. Write `meta.json`; fsync files and directories.
5. Rename the stage to `store/<digest>`; an existing digest is accepted only if
   its bytes and manifest hash match.
6. Atomically update `state.json`.
7. Return the installed digest and leave the plugin disabled.

Failure before step 5 leaves no store entry. Failure at step 6 leaves an
unreferenced store entry, which is collectable.

Concurrent installs of different plugins serialize on `state.lock`; store
payload writes may proceed in parallel only after the digest is known and may
not update state independently.

## 7. Update and rollback

Update is install of a new digest, then an atomic switch of `active_digest`.
The previous digest stays in `versions` for rollback.

- The running host is drained/stopped and its token revoked before switching.
- A failed switch leaves the old active digest and grants intact.
- No update auto-activates; restore `enabled` without starting a host.
- Rollback switches to a retained digest only if its manifest hash, API range,
  and permissions still satisfy the recorded grant.
- Downgrade is allowed only when the user confirms it.

## 8. Discovery and manager

Managed discovery resolves `active_digest` to `store/<digest>/root`.
Local discovery keeps scanning child directories of `ANVIL_PLUGIN_DIR`.
When both exist, managed state wins for the same id and reports the conflict.

Manager operations:

- list installed versions, source, digest, manifest hash, permissions, enabled;
- enable/disable without changing installed state;
- uninstall with reference-aware store cleanup;
- rollback to retained versions;
- show update availability only after an index slice exists.

## 9. Gateway and TUI changes

- Replace `pkg.install` destination handling with the store transaction.
- Add `pkg.state`/manager RPCs only when the manager slice starts.
- Remove automatic `enable_plugin` after install.
- Add local package install from a path; it uses the same verifier and store.
- Discovery reads managed state first, then `ANVIL_PLUGIN_DIR`.
- The current editor-session fetch remains transitional. The installer gateway
  role and `GatewayClient::fetch` split are a separate follow-up.

## 10. Test matrix

Store:

- duplicate digest install is idempotent;
- same id/version with different bytes is rejected;
- corrupt digest, signature, manifest, API range, and plugin id are rejected;
- archive traversal, links, devices, and absolute paths are rejected;
- stage failure leaves no store entry;
- store entry permissions are read-only for the user;
- state write failure leaves the old state readable.

State:

- concurrent installs of different ids preserve both state entries;
- concurrent install/update/uninstall of one id does not lose the last
  committed state;
- concurrent switches serialize and the active digest matches the last
  committed lock holder;
- `XDG_DATA_HOME` unset falls back to `$HOME/.local/share`;
- data root is `0700`, state/lock files are `0600`.
- missing state file is an empty store;
- corrupt and unsupported state versions fail closed;
- active digest missing from the store is reported and not loaded;
- permissions added/removed across versions force the expected consent path;
- uninstall keeps a digest referenced by another retained version;
- rollback rejects missing or mismatched digests.

Behavior:

- install does not enable or activate;
- enable after install runs the official trim-whitespace command;
- disable stops the host and keeps the package installed;
- uninstall removes the command from the palette;
- local user plugins do not enter state and cannot claim an official source;
- managed and local plugins with the same id report a conflict.

## 11. Delivery phases

1. Freeze this document and add the state/store ADR.
2. Add store path, digest, metadata, and atomic state primitives with tests.
3. Move `pkg.install` and the CLI install path onto the store.
4. Add managed discovery plus local-user conflict rules.
5. Remove install-time auto-enable.
6. Add local package install and the installed-plugin manager.
7. Only then split fetch into the installer gateway role.

## 12. Non-goals

- A public index or marketplace client.
- Automatic background updates.
- Multiple active digests for one plugin id.
- Storing mutable plugin directories as package identity.
- Running untrusted plugins outside the existing host sandbox.
