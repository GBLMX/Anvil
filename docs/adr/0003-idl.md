# ADR-0003: Lightweight IDL for the Ten-Method API

- Status: Accepted for v1
- Date: 2026-10-30
- Supersedes: "adopt Smithy before the API is frozen"

## Context

The v1 plugin API has four modules and ten methods. It needs Rust types,
TypeScript declarations, Lua stubs, JSON Schema for validation, and stable error
shapes.

Smithy is a capable IDL, but the cost is high for this surface:

- the Rust generator ecosystem is Kotlin-based and oriented toward AWS-style
  services;
- JSON-RPC 2.0 is not a built-in protocol; it needs a custom protocol generator;
- Lua generation still needs custom work;
- the build gains a JVM/Kotlin code-generation toolchain;
- the API can change during Phase 1, before the schema is stable.

The original plan placed Smithy in Phase 2b, after the Lua API. That would force
a second API migration after hand-written bindings already existed.

## Decision

1. The source of truth is a small set of Rust types in `anvil-api`.
2. Generate JSON Schema from those types with `schemars`.
3. Generate TypeScript declarations with `ts-rs`.
4. Generate Luau/LuaLS stubs from the schema with a small template, or
   maintain them by hand until the API freezes.
5. Freeze the ten method signatures before Phase 1 integration.
6. Do not adopt Smithy in v1. Run a one-week Smithy spike only if the team wants
   to challenge this decision; the spike must produce working Rust, TS, and Lua
   stubs for at least three methods within that week.
7. Revisit Smithy only when at least one of these is true:
   - the public API exceeds 30 methods;
   - multiple external SDKs need generated clients;
   - the team has an owned, tested protocol generator.

## API shape

The transport envelope is JSON-RPC 2.0. Method names and payloads are defined in
Rust and mirrored in generated artifacts.

| Module | Method | Permission |
|---|---|---|
| `editor` | `get_view` | `editor.read` |
| `editor` | `set_mode` | `editor.mode` |
| `editor` | `apply_edit` | `editor.write` |
| `editor` | `register_command` | `editor.commands` |
| `ui` | `notify` | `ui.notify` |
| `ui` | `status` | `ui.status` |
| `event` | `subscribe` | `event.read` |
| `sys` | `read_file` | `fs.read` |
| `sys` | `fetch` | `network` |
| `sys` | `exec` | `exec` |

`editor.get_view` returns the session `interaction_mode` with viewport and
selection. `editor.set_mode` switches it; Phase 0 accepts only `select`, and
unknown mode values are rejected as `invalid_request`.

All calls are asynchronous at the transport. Lua receives a blocking wrapper on
its own thread; QuickJS receives Promises. A request id can be cancelled.

## Error model

Stable error categories:

- `invalid_request`
- `permission_denied`
- `not_found`
- `timeout`
- `cancelled`
- `limit_exceeded`
- `policy_denied`
- `internal`

The error object carries a stable code, a human message, and an optional
`retryable` flag. Plugins must not parse message text.

## Consequences

Positive:

- No JVM/Kotlin build dependency in the critical path.
- The API can stabilize before code generation.
- TypeScript and JSON Schema come from one Rust definition.
- Lua stubs can track a stable schema instead of a moving target.

Negative:

- TypeScript and Lua generators are less capable than a full IDL ecosystem.
- Rust remains the source of truth; other languages are generated consumers.
- A future Smithy migration still needs an ADR and a compatibility plan.

## Alternatives considered

### Smithy in Phase 2b (rejected)

Too late: the Lua bindings would be written against a hand-made API and then
migrated. The code-generation cost is also understated.

### Hand-written everything (fallback)

Acceptable for ten methods if generation becomes a distraction. The schema and
versioning discipline still apply.

### OpenAPI/JSON Schema first

Viable, but the Rust types already exist for the runtime. Generating schema from
them avoids two sources of truth.

## Versioning

- Editor version and plugin API version are independent.
- Additive fields are minor versions.
- Removing or changing semantics is a breaking change with the charter's notice
  period.
- Generated stubs carry the API version; a plugin declares its required version
  in `Anvil.toml`.
