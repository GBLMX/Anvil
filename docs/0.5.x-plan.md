# 0.5.x Interaction and UI Plan

Status: planned. Depends on the `0.4.9` `anvil-session` extraction and the
registry/keymap phases in
[command-architecture-plan.md](command-architecture-plan.md). The Elm-style
runtime in [ratatui-elm-loop-plan.md](ratatui-elm-loop-plan.md) is the target
update/view boundary; features below must not add a second loop.

`0.5.0` completes the deferred `0.4.9` extraction: effects move from
`anvil-tui` into `anvil-session`; the command registry, focus state, and
overlay/input state are already session-owned. This happens before the
interaction slices below add new UI state.

Do not optimize old TUI code speculatively. Run the baseline and follow
[the early-code optimization policy](performance.md#12-early-code-optimization-policy)
before changing a hot path.

Scope: trusted, in-process terminal UI and native modal editing semantics.
Runtime plugins never draw UI.

## 1. Principles

1. **Core UI is trusted and in-process.** Plugins may contribute data, commands,
   and bounded preview text; they never own layout, focus, or rendering.
2. **Selection-first stays the native model.** Vim/Helix behaviors are adapters
   over selections and core actions, not a second editing kernel.
3. **First frame never waits.** Preview, symbol, diagnostic, and notification
   work is asynchronous, bounded, and generation-scoped.
4. **One focus owner.** Every overlay explicitly consumes input; `Esc` unwinds
   exactly one layer.
5. **Keyboard-first, mouse additive.** Every action available by mouse also has
   a keyboard path.
6. **No hidden state.** Loading, stale, degraded, and failed states are visible;
   no silent fallbacks.
7. **Bounded chrome.** Status, notifications, tabs, and pickers have caps and
   deterministic truncation/overflow behavior.
8. **Theme tokens only.** No hardcoded colors in views; color is never the only
   signal.
9. **One release, one bounded slice.** A slice is not complete while a follow-up
   release is required to make it usable.

## 3. Release slices

### 0.5.1: Last-change repeat

- Record the last successful mutating command, not raw keys.
- Descriptor: operator/action, motion/text object, original count, inserted
  text, and selection shape.
- `.` replays at the current caret; `3.` replaces the stored count.
- Do not record undo, redo, search, pure motion, or failed edits.
- Insert-session changes count as one unit.
- Define and test buffer-switch scope.
- Tests: `dw.`, `2dw` then `3.`, `ciwfoo<Esc>.`, `Afoo<Esc>.`,
  failed edit preserves the previous last change.

### 0.5.2: Operator, text-object, and selection adapters

- Generalize `d/y/c` over motions and text objects instead of one command per
  combination.
- Add `aw`, inner/outer quotes, brackets, parentheses, braces, paragraphs, and
  tags; unknown objects fail without changing state.
- Map Vim visual/line/block intent onto the selection-first model.
- Do not add a native visual mode to `anvil-core`; block selection requires a
  selection-shape decision first.
- Tests: count combinations, empty selection, multi-selection, undo grouping,
  object failure, direction reversal.

### 0.5.3: Command palette and which-key

- Build the palette from the command registry; do not maintain a second command
  list.
- Show canonical command ID, title, keybinding, context, and disabled reason.
- Fuzzy ranking over title/ID/aliases; recent commands first on an empty query.
- Which-key uses the same keymap trie/registry and shows legal continuations.
- One focus/overlay stack; palette closes on execute, `Esc`, or focus loss.
- Tests: duplicate IDs, disabled commands, keybinding display, nested prefixes,
  timeout, very narrow width.

### 0.5.4: Quick-open preview and icon theme

- Preview the selected file through the gateway, not `std::fs`.
- Bounded by bytes, lines, and time; discard stale generations.
- First frame and list navigation never wait for preview.
- Preview failure shows an explicit message and keeps the list usable.
- Icon theme is data: `extension/name -> glyph + color`, with a text fallback.
- Tests: truncated file, binary/invalid UTF-8, stale preview, gateway failure,
  unknown extension, double-width and ambiguous-width glyphs.

### 0.5.5: Breadcrumbs and status line

- Breadcrumbs derive from workspace-relative path plus the selected symbol;
  they never do synchronous parsing.
- Status segments have explicit priority and width caps: mode, path, dirty,
  branch, diagnostics, LSP, selection count, cursor position.
- Truncation is deterministic; no segment may panic on small widths.
- Degraded gateway/LSP/plugin states are visible but non-modal.
- Tests: 40/80/200-column layouts, long paths, missing symbols, multiple
  diagnostics, stale LSP state.

### 0.5.6: Buffers and tabs

- Add a tab/buffer bar with active, dirty, read-only, and missing-file states.
- Close guard reuses the existing unsaved-change path.
- Overflow behavior is explicit: scroll, compact labels, or a buffer picker.
- Switching tabs preserves cursor, scroll, selections, and LSP state.
- Tests: dirty close, read-only, deleted file, many buffers, split focus,
  session restore boundary.

### 0.5.7: Notifications, progress, and problems

- Bounded notification queue with severity, source, timestamp, and dismiss.
- No modal notification for recoverable errors; progress is non-blocking and
  cancellable where the operation supports it.
- Problems panel lists diagnostics with file/severity/source and jump-to.
- Duplicate/stale diagnostics must not accumulate across edits.
- Tests: queue cap, duplicate coalescing, progress completion/failure, jump to
  stale diagnostic, narrow panel.

### 0.5.8: Search and replace UI

- Incremental search highlighting with match count and current-match indicator.
- Regex toggle, whole-word toggle, case sensitivity, and explicit invalid-regex
  error state.
- Replace one/replace all applies as one undo transaction.
- No replacement while the buffer is read-only; no partial mutation on error.
- Tests: empty query, regex errors, overlapping matches, replace-all undo,
  read-only, Unicode boundaries.

### 0.5.9: Mouse, focus, and accessibility

- Mouse hit-testing for editor, tree, tabs, status, splits, and overlays.
- Drag selection, wheel scroll, split resize, click-to-focus.
- Focus is single-owner and restored after overlay close.
- Keyboard equivalents remain for every mouse action.
- Contrast/ASCII fallback for unsupported glyphs; no color-only severity.
- Tests: hit-test boundaries, drag across wide glyphs, overlay focus trap,
  narrow/legacy terminal fallback.

### Deferred: optional UI effects (TachyonFX)

Status: exploratory; not part of `0.5.1`–`0.5.9`. Do not add the dependency
until the UI baseline and performance gates pass.

- Scope: `anvil-tui` only, behind a non-default `effects` feature.
- Required before code: an ADR covering dependency category, duration/frame
  budget, reduced-motion/NO_COLOR/tmux fallbacks, and version compatibility.
- Effects run only during an explicit transition; idle redraw and tick must be
  zero after the effect completes.
- No effect on text input, cursor movement, scrolling, or LSP-critical paths.
- No plugin effect API and no marketplace-installable effects.
- Promote only if first-frame, key-to-screen, and scroll p99 gates remain within
  budget; otherwise keep the dependency out.

## 4. Interaction architecture

```text
terminal event
  -> Focus::dispatch_one
  -> OverlayStack (top owns input)
  -> CommandRegistry / keymap trie
  -> editor command or bounded effect
  -> Msg -> update -> render
```

Required state boundaries:

- `Focus`: editor, tree, picker, palette, notification, problems, tab bar.
- `OverlayStack`: completion, hover, diagnostics, symbols, palette, preview.
- `CommandRegistry`: canonical command metadata; palette and which-key consume
  it.
- `PickerState`: query, filtered entries, selected index, preview generation.
- `NotificationQueue`: bounded, deduplicated, severity ordered.
- `StatusModel`: computed segments, not renderer-local strings.
- `Layout`: pure function of terminal size and focus; no I/O, no unbounded
  iteration.

Rules:

- `update` never reads files, starts processes, or blocks.
- Async results carry path, request ID, and revision; stale results are dropped.
- Overlays render after the editor and before the status line.
- One redraw per state change; no fixed frame loop.
- Plugin data enters through bounded values, never callbacks that render.

## 5. Non-goals

- No GUI/webview, floating windows, minimap, image protocols, or default smooth
  animation. Optional TachyonFX-style effects are deferred and require the ADR
  and feature gate above.
- No plugin-owned UI or arbitrary terminal escape output.
- No plugin marketplace, package installer, or download manager. Those are
  distribution work in [0.6.x-plan.md](0.6.x-plan.md).
- No mouse-first redesign.
- No Vimscript compatibility or second native modal kernel.
- No recursive tree watching, unbounded previews, or unbounded notification
  history.
- No new external runtime dependency without an ADR.

## 6. Exit gates

Every slice must satisfy the gates in [RELEASE.md](../RELEASE.md), update
`CHANGELOG.md` and the relevant docs, and pass an installed-binary smoke test.

Additional interaction gates:

- `cargo test --workspace --no-fail-fast` passes.
- `cargo clippy --workspace --all-targets -- -D warnings` passes.
- `cargo fmt --all -- --check` and `git diff --check` are clean.
- Render tests cover 40×12, 80×24, and 200×50.
- First-frame timing is unchanged by preview/palette additions.
- No overlay can steal input without recording focus ownership.
- No asynchronous result can overwrite a newer revision.
