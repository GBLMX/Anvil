# 0.4.x Feature Plan

Status: closed. The `0.4.x` line landed through `0.4.9`; its remaining
session extraction completed in `0.5.0`.

One release carries one bounded feature slice plus its tests and documentation.
A slice is not complete while it needs a follow-up release to be usable.

## 0.4.1: Workspace tree watcher

- Status: released as `0.4.1` on 2026-11-01; installed binaries verified.
- Gateway `sys.read_dir_signature` with `fs.read` and `openat2` confinement.
- Root plus expanded-directory polling; 500 ms poll and 500 ms debounce.
- Coalesced `TreeChanged`; 256-directory cap; `Files · stale` and
  `Files · watch limit`.
- Generation-scoped snapshots preserve selection and expansion; background
  refresh does not steal focus; missing new expansion queues a follow-up.
- Inode-based selection matching covers external rename; verified end-to-end
  and [#9](https://github.com/GBLMX/Anvil/issues/9) closed.
- Add `INSTALL.md` and verify the installed sibling binaries.
- Install guide: [INSTALL.md](../INSTALL.md).
- ADR: [0018](adr/0018-workspace-tree-watch.md).

## 0.4.2: Syntax highlighting coverage

- Status: released as `0.4.2` on 2026-11-01.
- Static compiled-query registry keyed by file name and extension.
- TOML, Go, Bash, Python, YAML, JSONC, Makefile, Dockerfile, and `go.mod`.
- `go.mod` uses a bounded directive/comment/string scanner.
- Rust keyword walking is limited to Rust.
- Unsupported formats remain plain text; 256 KiB cap remains.
- Tests cover detection, per-format classes, JSONC comments, and `go.mod`.

## 0.4.3: Markdown highlighting

- Status: released as `0.4.3` on 2026-11-01.
- `tree-sitter-md` block and inline grammars without a second tree-sitter
  runtime.
- Heading, link, code, emphasis, list, quote, table, and frontmatter classes.
- Fenced code uses the nested language grammar when available.
- Tests cover malformed fences, frontmatter, and every Markdown class.

## 0.4.4: Gateway capability control plane

- Status: landed in `0.4.5`; gateway API + Rust client. Editor spawn wiring
  remains in `0.4.6`.
- Add control-socket `register`/`revoke` for per-plugin `(id, token_hash,
  workspace, grants)`.
- Define the capability table (`fs.read`, `fs.write`, `sys.fetch`, `sys.exec`)
  and fail-closed matching.
- Register before spawn; revoke on stop, crash, or failed handshake.
- No plugin loading and no host lifecycle change in this slice.
- Tests: wrong workspace, missing grant, token reuse, revoke race, concurrent
  registration.

## 0.4.5: Manifest and host loading

- Status: released as `0.4.5` on 2026-11-02.
- Add a versioned manifest format with bounded size, activation events, and a
  unique command index.
- Load one Luau entry from a validated plugin directory.
- Preserve token-FD delivery, sandbox setup, and the editor handshake.
- Failed validation, spawn, sandbox, or handshake kills the host.
- No supervisor restart/idle policy or finished spawn-after-registration wiring
  yet; those move to `0.4.6`.

## 0.4.6: Activation and supervisor lifecycle

- Status: 0.4.6a landed: `PluginSession` registers the grant before spawn,
  handshakes the host, and revokes on stop or failure. Manifest discovery from
  `ANVIL_PLUGIN_DIR` is landed as the activation prerequisite. 0.4.6b landed:
  startup, language, and workspace-marker activation matching starts hosts with
  an empty grant set and keys sessions by plugin id. 0.4.6c landed: the host
  supervisor owns `Unloaded -> Queued -> Registering -> Starting -> Ready ->
  Draining -> Stopped`, with `Failed` and explicit `Disabled` states,
  single-flight startup, a bounded start queue, start timeout, crash backoff,
  queue-until-ready calls, drain-before-kill, response-id validation, and
  `:plugin-enable <id>`. `onCommand` events are parsed but not dispatched until
  the command index is wired; that remains a separate slice.
- Wire `HostSession` spawn through gateway `plugin.register`/`revoke` and the
  editor/gateway handshake before enabling activation dispatch.
- Match activation events to manifests without granting capabilities.
- Implement `Unloaded -> Queued -> Registering -> Starting -> Ready ->
  Draining -> Stopped`, with `Failed`/`Disabled`.
- Single-flight startup per plugin, bounded running and queued-start caps,
  request timeouts, crash backoff, and drain-before-kill.
- Queue requests until `Ready`; a failed start fails only that plugin's waiters.
- Repeated failures disable the plugin until the user runs
  `:plugin-enable <id>`; `Failed` retries remain bounded by the backoff window.

## 0.4.7: Resource isolation and idle reclaim

- Status: 0.4.7a landed: cgroup creation and placement before `execve`,
  mandatory `memory.max`/`memory.swap.max`/`pids.max`/`cpu.weight`, unique
  per-host cgroups, `pidfd` stop, `cgroup.kill` fallback, `RLIMIT_CORE=0`,
  `PR_SET_DUMPABLE=0`, PDEATHSIG race check, and global running/queued-start
  caps. 0.4.7b landed: idle hosts are drained, stopped, revoked, and removed
  after 60 seconds without activity. 0.4.7c-a/b landed: the editor Unix socket
  is preconnected before Landlock/seccomp, and the seccomp denylist closes
  signal, async-SIGIO, memory-execution, namespace/mount, introspection,
  `clone3`, and post-sandbox socket/connect paths.
- Require delegated cgroup v2 with `memory.max`, `pids.max`, and CPU weight;
  missing limits fail closed.
- Add global running-host and queued-start caps.
- Terminate idle hosts, revoke tokens, remove sockets/cgroups, and reap
  process groups.
- Tests: OOM classification, pids exhaustion, orphan cleanup, idle reclaim,
  crash/restart loops.

## 0.4.8: Plugin I/O and document transactions

- Status: 0.4.8a landed: `DocumentSnapshot`, `ApplyEditRequest`,
  `ApplyEditResponse`, `TextRange`, and `DocumentEdit` DTOs; `METHODS` is the
  single method/params/result catalog used by generated JSON, TypeScript, and
  Lua method bindings. 0.4.8b landed: the plugin host preconnects the gateway
  before sandboxing and forwards `sys.*` through the authenticated
  `GatewayClient`. 0.4.8c landed: `EditorState::apply_transaction_at` and the
  TUI snapshot/transaction contract validate base revisions, reject stale or
  invalid edits, and report rejection in the existing status bar.
- This slice is API/headless except for existing status-bar rejection/audit
  notices. Full permission/audit panels and command/notification UI depend on
  `0.5.x`; `onCommand` is not complete before that layer.
- Route plugin `sys.*` through the gateway with the plugin token and grants.
- Add a read-only document snapshot plus transaction contract with base
  revision and explicit conflict errors.
- Emit rejected-operation and permission/audit details to the existing status
  bar; full permission/audit panels are `0.5.x`.
- Tests: outside-workspace I/O, revoked grant, stale revision, conflicting
  transaction, plugin death mid-request.

## 0.4.9: Protocol and session boundaries

- Status: 0.4.9 landed with an explicit rescope. Landed: host `session.hello`
  carries `api_version`, plugin manifests validate the `0.1` API line,
  `anvil-session` owns active document state, the command registry, plugin
  document transactions, and plugin host lifecycle. Focus/overlay state and
  effects landed in `0.5.0`. Typed `sys.*` DTOs are scheduled before the
  `0.6.0` API freeze.
- Version the gateway protocol and add compatibility tests for every new
  control and plugin method.
- Add API version negotiation to `session.hello` on both sides and a required
  API range in the plugin manifest; missing or incompatible versions fail
  before plugin loading.
- Start `docs/spec/plugin-api.md` as a draft normative SPEC: envelope,
  handshake, method catalog, DTO semantics, errors, permissions, cancellation,
  and compatibility. It is not stable until the `0.6.0` freeze.
- Extract `anvil-session` from the TUI so a frontend can use the kernel without
  forking the terminal UI.
- Keep the interim TUI keymap separate from kernel semantics.

Every `0.4.x` release must satisfy the gates in
[RELEASE.md](../RELEASE.md), update `CHANGELOG.md`, `ROADMAP.md`, the relevant
known issues/ADR, and pass an installed-binary smoke test.
