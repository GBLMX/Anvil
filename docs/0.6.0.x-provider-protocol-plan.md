# 0.6.0.x Provider Protocol Plan

Status: `0.6.0.1` provider foundation and `0.6.0.2` PickerSource are landed;
`0.6.0.3` and later are proposed. The Cargo version remains `0.6.0`; the `0.6.0.x` labels are planning
labels, not releases or semver tags.

Related: [ADR-0037](adr/0037-kernel-api-baseline.md),
[ADR-0024](adr/0024-tui-state-and-domain-boundaries.md),
[ADR-0025](adr/0025-lsp-and-language-breadth.md),
[0.7.x modules](0.7.x-plan.md), [internal polish](internal-polish-plan.md).

## 1. Goal

Add UI-neutral provider protocols for editor capabilities that currently have
one hard-coded implementation:

- picker sources;
- completion sources;
- formatter providers;
- test adapters;
- DAP adapter descriptors.

The goal is not a general plugin ABI. The goal is fewer reasons for every
feature to depend on `anvil-tui::Model`.

## 2. Constraints

- Version is frozen at `0.6.0`; do not bump Cargo versions or create tags.
- Do not restart the full ADR-0024 state refactor. Keep `Model` composition.
- `anvil-tui` remains the UI adapter and renderer.
- Provider traits and DTOs must not depend on `ratatui` or `crossterm`.
- A provider never receives `&mut Model`.
- A provider returns data; core owns selection, insertion, undo, ranking, and
  lifecycle.
- One protocol has multiple providers from day one. Do not repeat the single
  `LanguageToolingService` slot pattern.
- Runtime Luau providers are data-only and capability-checked.
- Process execution follows the class boundaries in section 3.

## 3. Execution classes

| Class | Used by | Execution |
|---|---|---|
| Data-only | picker, completion | no process; provider returns data |
| One-shot tool | formatter, linter, test runner | gateway one-shot `sys.exec.v2` with bounded stdin/cwd/output |
| Long-lived adapter | LSP | existing gateway `lsp.start` |
| Long-lived adapter | DAP | trusted direct-spawn exception owned by core |

### 3.1 One-shot exec v2

Formatter, linter, and test adapters need stdin and cwd. The current
`ExecRequest { tool, args, timeout_ms }` is insufficient.

Add a versioned one-shot request:

```rust
pub struct ExecRequestV2 {
    pub tool: String,
    pub args: Vec<String>,
    pub cwd: Option<String>,
    pub stdin: Option<String>,
    pub timeout_ms: u64,
    pub max_stdout_bytes: u64,
    pub max_stderr_bytes: u64,
}
```

Rules:

- `cwd` is workspace-relative and root-confined; reject absolute or escaping
  paths.
- stdin and outputs are bounded and rejected before execution when oversized.
- no shell parsing; `args` remains an argv vector.
- no arbitrary environment map in this slice. Environment support needs a
  separate policy and ADR.
- exec-runner continues to apply Landlock/seccomp.
- keep `sys.exec` v1 unchanged for existing callers.

### 3.2 DAP exception

DAP needs a long-lived bidirectional stdio process. A generic gateway process
broker is a separate substrate project, not part of `0.6.0.x`.

Decision:

```text
DAP adapters are trusted external tools, like LSP servers.
The core DAP manager may spawn them directly.
```

The exception is bounded:

- only builtin adapters and trusted Rust modules may provide DAP adapters;
- Luau runtime plugins may not provide DAP adapters;
- the core owns process creation, cwd, process group, frame cap, shutdown, and
  restart;
- providers return `DapAdapterSpec`, never a `Child` or a stdio handle.

## 4. Target ownership

```text
anvil-api
  ModuleId
  wire DTOs: ExecRequestV2, provider DTOs if needed by plugins

anvil-core / anvil-editor
  text, coordinates, selection, snapshots, edit semantics

anvil-session
  ProviderId, ProviderRegistry, ProviderError, CancellationToken
  PickerSource, CompletionSource, FormatterProvider, TestAdapter,
  DapAdapterProvider
  no ratatui/crossterm

anvil-module
  existing module contract v1 unchanged
  modules may implement provider traits from anvil-session

anvil-tui
  picker/completion/format UI adapters
  request orchestration for the TUI lifetime

anvil-mod-*
  provider implementations

anvil-plugin-host
  Luau provider bridge
  data-only picker/completion in this plan
```

Provider registration is explicit in distribution composition. Do not change
the frozen `anvil-module` contract until a provider slot is needed by a
third-party module and the contract impact is reviewed.

Dependency rule: `anvil-session` must not depend on `anvil-module`.
Provider provenance uses `anvil_api::ModuleId`; `anvil-module` re-exports that
same type, so modules and providers share one identity without a cycle.

## 5. Core protocol types

### 5.1 Identity and registry

```rust
pub struct ProviderId(Arc<str>);

pub enum ProviderOrigin {
    Builtin,
    RustModule(ModuleId),
    RuntimePlugin(Arc<str>),
}

pub struct ProviderPriority(i32);

pub struct ProviderRegistry<T: ?Sized> {
    // ordered by priority, then id
}
```

`ModuleId` lives in `anvil-api`. `anvil-module` re-exports it for module
authors. Runtime plugin ids are dynamic and use `Arc<str>`.

Requirements:

- duplicate ids fail registration;
- ordering is deterministic;
- unregister cancels outstanding work;
- provenance is visible in diagnostics;
- no implicit "last registration wins".

### 5.2 Cancellation and errors

```rust
pub struct CancellationToken {
    cancelled: Arc<AtomicBool>,
}

pub enum ProviderError {
    Unavailable,
    Cancelled,
    Timeout,
    InvalidData(String),
    Internal(String),
}
```

`None`, empty, unavailable, cancelled, and failed are distinct states.

## 6. Protocol contracts

### 6.1 PickerSource

```rust
pub struct PickerQuery {
    pub text: String,
    pub root: PathBuf,
    pub revision: u64,
    pub limit: usize,
}

pub struct PickerEntry {
    pub value: serde_json::Value,
    pub ordinal: String,
    pub display: DisplayRow,
}

pub trait PickerSource: Send + Sync {
    fn id(&self) -> ProviderId;

    fn is_available(&self, ctx: &PickerContext) -> bool;

    fn query(
        &self,
        query: &PickerQuery,
        cancel: &CancellationToken,
        emit: &mut dyn FnMut(Vec<PickerEntry>),
    ) -> Result<(), ProviderError>;

    fn preview(
        &self,
        entry: &PickerEntry,
    ) -> Result<Option<Preview>, ProviderError> {
        Ok(None)
    }
}
```

Core owns merging, deduplication, sorting, selection, multi-select, and action
dispatch. The provider only supplies entries.

### 6.2 CompletionSource

```rust
pub struct CompletionContext {
    pub path: Option<PathBuf>,
    pub language_id: String,
    pub revision: u64,
    pub cursor_utf16: (u32, u32),
    pub prefix: String,
    pub trigger: Option<char>,
}

pub struct CompletionItem {
    pub label: String,
    pub detail: Option<String>,
    pub insert_text: String,
    pub filter_text: Option<String>,
    pub sort_text: Option<String>,
    pub kind: CompletionKind,
    pub text_edit: Option<TextEdit>,
    pub documentation: Option<Markup>,
}

pub trait CompletionSource: Send + Sync {
    fn id(&self) -> ProviderId;

    fn trigger_characters(&self) -> Vec<char>;

    fn is_available(&self, ctx: &CompletionContext) -> bool;

    fn complete(
        &self,
        ctx: &CompletionContext,
        cancel: &CancellationToken,
    ) -> Result<Vec<CompletionItem>, ProviderError>;

    fn resolve(
        &self,
        item: &CompletionItem,
    ) -> Result<CompletionItem, ProviderError> {
        Ok(item.clone())
    }
}
```

The core owns insertion ranges, snippet sessions, menu state, revision checks,
and final ranking. Source order is not merge order.

### 6.3 FormatterProvider

```rust
pub struct FormatterSpec {
    pub id: ProviderId,
    pub command: String,
    pub args: Vec<String>,
    pub stdin: bool,
    pub cwd: CwdStrategy,
    pub range_args: Option<RangeArgs>,
    pub exit_codes: Vec<i32>,
    pub timeout: Duration,
}

pub trait FormatterProvider: Send + Sync {
    fn formatter_for(&self, ctx: &FormatContext) -> Option<FormatterSpec>;
}
```

The core format service:

- resolves the spec;
- computes range args;
- calls `sys.exec.v2`;
- validates exit code and output bounds;
- applies edits only if the buffer revision is unchanged.

First version supports stdin-to-stdout formatters only. In-place and tempfile
formatters return `ProviderError::Unavailable`.

### 6.4 TestAdapter

```rust
pub trait TestAdapter: Send + Sync {
    fn id(&self) -> ProviderId;

    fn discover(&self, ctx: &TestContext) -> Result<TestTree, ProviderError>;

    fn build_spec(
        &self,
        test_id: &TestId,
        ctx: &TestContext,
    ) -> Result<TestCommandSpec, ProviderError>;

    fn parse_results(
        &self,
        test_id: &TestId,
        output: &ExecResponse,
    ) -> Result<TestResult, ProviderError>;
}
```

Test commands use `sys.exec.v2`; no provider-spawned processes.

### 6.5 DapAdapterProvider

```rust
pub struct DapAdapterSpec {
    pub id: String,
    pub program: PathBuf,
    pub args: Vec<String>,
    pub cwd: PathBuf,
    pub transport: DapTransport,
}

pub trait DapAdapterProvider: Send + Sync {
    fn adapter_for(&self, ctx: &DapContext) -> Option<DapAdapterSpec>;
}
```

Only builtin and trusted Rust modules implement this trait. The core DAP manager
owns direct spawn and lifecycle.

## 8. Slice details

### 0.6.0.1 Provider foundation

Scope:

- `anvil-session/src/provider/{mod,id,error,cancel,registry}.rs`;
- prerequisite: `ModuleId` lives in `anvil-api` and is re-exported by
  `anvil-module`;
- `ProviderId`, `ProviderOrigin`, `ProviderPriority`, `ProviderError`;
- `CancellationToken`;
- `ProviderRegistry<T>`;
- no TUI changes;
- no user-visible behavior.

Tests:

- duplicate id rejected;
- deterministic priority order;
- unregister removes provider and cancels outstanding token;
- unavailable/empty/cancelled/error remain distinct;
- `anvil-session` has no `anvil-tui` dependency.

Exit gate:

```text
cargo test -p anvil-session
cargo clippy -p anvil-session --all-targets -- -D warnings
cargo tree -p anvil-session | grep anvil-tui  # must be empty
```

### 0.6.0.2 PickerSource

Scope:

- UI-neutral picker DTOs and trait in `anvil-session`;
- a TUI picker engine that owns request generation, cancellation, and stale
  result rejection;
- one existing source converted first: buffer picker or current LSP symbols;
- preview and action remain core-owned;
- no runtime plugin registration yet.

Do not migrate every existing picker in this slice.

Tests:

- fake source emits multiple batches;
- close/cancel drops late batches;
- stale revision/generation is ignored;
- duplicate entries deduplicate by stable key;
- priority order is deterministic;
- preview is optional;
- empty and error states render distinctly.

Exit gate:

- one real source path works through the new protocol;
- existing picker behavior remains available during migration;
- no provider API takes `&mut Model`;
- TUI smoke passes.

### 0.6.0.3 CompletionSource

Scope:

- completion DTOs and trait;
- LSP source adapter over the existing worker;
- buffer-word source;
- path source;
- source id on every item;
- core-owned merge, dedup, and ranking;
- revision checks before insertion.

Do not add arbitrary plugin completion yet.

Tests:

- LSP + buffer + path merge;
- ranking and `sortText`/`filterText` behavior;
- stale completion response is rejected;
- cancel closes all in-flight source work;
- snippet insertion remains core-owned;
- malformed item payload is rejected.

Exit gate:

- existing LSP completion tests pass;
- new sources are opt-in through registry;
- no second event loop.

### 0.6.0.4 Exec v2 and FormatterProvider

Scope:

- `ExecRequestV2` and `sys.exec.v2` in Rust API/client;
- Go gateway and exec-runner stdin/cwd/output bounds;
- formatter registry and core format service;
- stdin-to-stdout only;
- LSP formatting remains available and is not replaced.

Tests:

- stdin reaches the child;
- cwd is root-confined;
- absolute or escaping cwd is rejected;
- stdout/stderr caps;
- nonzero exit and timeout map to distinct errors;
- cancelled formatter does not apply edits;
- buffer revision change discards result;
- in-place/tempfile formatter is explicitly unavailable.

Exit gate:

- security review of the new exec fields;
- no arbitrary env;
- existing `sys.exec` v1 callers unchanged;
- Go tests/vet and Rust smoke pass.

### 0.6.0.5 DAP adapter boundary

Scope:

- `DapAdapterSpec` and `DapAdapterProvider`;
- core-owned `DapAdapterManager`;
- direct-spawn exception documented and tested;
- runtime plugin DAP provider rejected at registration.

No generic gateway process broker in this plan.

Tests:

- builtin/rust provider adapter is accepted;
- runtime plugin adapter is rejected;
- cwd/allowlist validation;
- adapter shutdown kills the process group;
- message cap remains enforced.

### 0.6.0.6 Runtime plugin provider bridge

Scope:

- `editor.register_provider` and `provider.request` / `provider.cancel`;
- picker and completion only;
- no formatter/DAP from Luau in this plan;
- request ids, cancellation, payload caps, malformed payload rejection;
- plugin disable unregisters providers and drops results.

Tests:

- register/unregister;
- capability/namespace check;
- duplicate id;
- cancel;
- stale response;
- payload over cap;
- plugin exit/reload cleanup.

Exit gate:

- provider registration cannot grant process/filesystem/network authority;
- plugin provider results remain data-only.

### 0.6.0.7 Hardening and exit gate

- Full workspace tests, clippy, fmt.
- Feature matrix for no modules, each module, all modules.
- Minimal fixture.
- Installed-binary picker/completion smoke.
- No new `anvil-tui` dependency in kernel or modules.
- Update `CHANGELOG.md`, `README.md`, and architecture docs.
- Add known limitations for unsupported formatter modes and DAP exception.

## 9. Test matrix

| Area | Required |
|---|---|
| registry | duplicate id, priority, unregister, provenance |
| cancellation | close, disable, timeout, stale |
| picker | batches, dedup, preview, empty/error |
| completion | merge, ranking, revision, malformed payload |
| exec v2 | stdin, cwd, caps, exit code, timeout |
| formatter | stdin only, no revision overwrite |
| DAP | trusted-only, cleanup, frame cap |
| plugin bridge | registration, cancel, disable, caps |
| architecture | no TUI dependency from kernel/modules |

## 10. Risks

| Risk | Mitigation |
|---|---|
| Provider traits leak UI types | compile-time dependency check |
| Single-slot registry repeated | multi-provider registry from day one |
| Cancellation races | generation + revision + explicit tests |
| Exec v2 expands attack surface | root-confined cwd, caps, no env, security review |
| DAP direct spawn inconsistent | explicit trusted exception and manager |
| Runtime plugin bridge becomes an ABI | keep it data-only, version it |
| Full Model refactor creep | only extract protocol seams; no ADR-0024 restart |
| Provider ordering instability | explicit priority and deterministic tie-break |

## 11. Non-goals

- Stable Rust ABI for providers.
- Generic gateway process/stdio broker.
- In-place or tempfile formatters in `0.6.0.x`.
- Luau DAP or formatter providers.
- AI provider protocols.
- Marketplace provider installation.
- Full Model state split.
- Making trusted Rust providers sandboxed.

## 12. Exit criteria

- `0.6.0.1`–`0.6.0.6` complete with tests.
- One real picker source and one real completion source use the new protocols.
- Formatter stdin path is bounded and security reviewed.
- DAP exception is documented and enforced.
- Runtime plugin provider registration is data-only.
- Full workspace gates and installed-binary smoke pass.
- Cargo version remains `0.6.0`.
