# 0.7.x Official Optional Rust Modules Plan

Status: 0.7.1 contract ADR and `anvil-module` registry landed (ADR-0028).
`0.4.9` `anvil-session` extraction, the `0.6.0` plugin API v1 freeze, the
standard-edition composition crate, and the ADR-0013 two-consumer gate are
landed. Git extension points are defined (ADR-0029). Migration slices 1–2 have
moved the pure Git helpers into `anvil-mod-git`, added the `GitService` trait,
and injected it into `FileWorker`. TUI startup now accepts an optional
`GitService`; the minimal fixture passes `None`. `official-git` is now a real
Cargo feature: standard enables it by default, minimal disables default
features, and `anvil-mod-git` is absent from the minimal feature graph. `:git-*` commands are
gated at dispatch, and command-line completion hides them when the service is
absent. Remaining: register `official.git` through `ModuleRegistry`, then run
the installed-binary parity smoke.

Scope: trusted, source-level Rust modules compiled into a distribution. This is
not a runtime plugin system and not a stable Rust ABI.

## 1. Principles

1. **Compile-time only.** No `dlopen`, `.so`, dynamic Rust ABI, or hot loading.
2. **Trusted distribution code.** A Rust module runs in-process with kernel
   trust; it is not sandboxed and must not be advertised as a plugin.
3. **Kernel owns semantics.** Modules may compose kernel commands and services;
   they must not redefine text, selection, undo, or sandbox policy.
4. **Optional means feature-gated.** A module is a separate crate plus a Cargo
   feature; the standard edition chooses its curated set.
5. **No marketplace installation.** Rust modules ship with the distribution;
   Lua/TS plugins remain the only marketplace-installable runtime code.
6. **Mediated I/O.** Modules use kernel/session/gateway APIs; no direct
   privileged filesystem or network path.
7. **No silent capability widening.** A module cannot grant plugin capabilities,
   weaken Landlock/seccomp, or bypass gateway policy.
8. **Compatibility is source-level.** Kernel crates use semver; a module pins a
   compatible kernel range and is rebuilt by the distribution.

## 2. Module contract

A module is:

```text
anvil-mod-<name> crate
  -> depends on anvil-session / anvil-api / anvil-editor as needed
  -> exposes a typed registration function
  -> is selected by the distribution composition crate
  -> is compiled into the final binary
```

Required metadata:

- stable module id and human name;
- kernel/module API version range;
- contributed commands, views, providers, and background services;
- explicit gateway capabilities it uses;
- startup and shutdown ordering;
- feature flag and default-standard-edition inclusion;
- owner and support status.

Rules:

- Module ids and command ids are namespaced; collisions fail the build or
  startup validation.
- A module cannot replace a core command implementation by shadowing an id.
- Registration is explicit and deterministic; there is no scanning or runtime
  discovery.
- Startup failure of an optional module is reported and may disable that module
  without taking down the editor only where the composition crate can prove
  isolation; otherwise the binary fails closed.
- Modules must not add a second UI event loop or bypass the focus/overlay stack.

## 3. Release slices

### 0.7.1: Module contract and `anvil-mod-git`

- Add the module-contract ADR, typed registration API, feature matrix, and
  collision validation.
- Move the existing git gutter/status integration into an optional
  `anvil-mod-git` crate.
- Standard edition includes it by default; a feature-free composition excludes
  it.
- No new I/O path: git access still goes through the established gateway/exec
  boundary where required.
- Tests: no-module build, module-only build, command collision, duplicate
  module id, missing kernel feature, git module behavior parity.

### 0.7.2: `anvil-mod-workspace-index`

- Add an optional workspace index/search service as a trusted module.
- Bounded indexing, cancellation, stale-result handling, and memory/disk caps.
- No direct filesystem bypass; use the gateway/session file APIs.
- The module can be excluded without breaking editing, LSP, tree, or search.
- Tests: empty workspace, large workspace, cancellation, stale results, index
  corruption, feature-free build.

### 0.7.3: Third-party distribution fixture and compatibility gate

- Build an independent consumer that composes the kernel with a different UI or
  module set.
- Prove the official standard edition and the independent fixture compile
  against the same kernel/module contract.
- Add a module compatibility matrix and deprecation policy.
- Freeze the module contract candidate only after both consumers pass.
- Tests: feature permutations, version mismatch diagnostics, independent
  composition, no dependency on `anvil-tui` internals.

### 0.7.4: Additional official modules

Only after 0.7.3:

- desktop/XDG integration where it adds value over runtime plugins;
- optional language/tooling providers that need trusted in-process access;
- additional workspace services with explicit caps.

Each module gets its own bounded release slice; do not bundle unrelated modules
into 0.7.1.

## 4. Candidate boundaries

| Candidate | Fit | Reason |
|---|---|---|
| `anvil-mod-git` | first | Exposes an existing trusted integration and exercises optionality |
| `anvil-mod-workspace-index` | second | Performance-sensitive trusted workspace service |
| desktop/XDG integration | later | Useful but must not become a privileged escape hatch |
| core editing/kernel semantics | never | Must remain in kernel crates |
| runtime Lua/TS plugin | never | Uses plugin-host and marketplace instead |

## 5. Security and trust

- Rust modules are trusted code; review, distribution signing, and release
  provenance are mandatory.
- A module cannot install another module, spawn an unsandboxed process, or
  receive a plugin token.
- Module I/O that needs filesystem/network/exec routes through the gateway and
  the same policy checks as other callers.
- A module cannot change `sys.*` grants or the exec-runner sandbox.
- If a module panics, the composition crate decides fail-closed vs
  module-disable; the default must not leave editor state half-mutated.

## 6. Non-goals

- Stable Rust ABI or dynamic Rust plugins.
- Loading Rust modules from the marketplace or a workspace.
- Sandboxing trusted Rust modules.
- Moving core editing semantics out of kernel crates.
- A public module ecosystem before the two-consumer gate.
- Windows/macOS module variants in v1.

## 7. Exit gates

Every slice follows [RELEASE.md](../RELEASE.md), updates `CHANGELOG.md`,
`ROADMAP.md`, and the module ADR, and passes:

- `cargo test --workspace --no-fail-fast`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo fmt --all -- --check`
- feature-matrix builds: no modules, each module, all modules
- installed-binary smoke test with the standard edition
- independent composition fixture
- no module depends on `anvil-tui` internals
- no module introduces a direct privileged I/O path
